# U6 — что снять руками

Снимки делает владелец (решение 2026-09-16). PR оставляет **список**, а не картинки.

Куда класть: `docs/screens/<AVD>/<NN-экран>/<состояние>.png`, `screencap` как есть, без обработки.
Устройства — `Sm29` (API 29, 360×640 dp) и `BigScaled` (540 dpi, шрифт ×1.3, 398×887 dp).

Перед проходом: `am force-stop` + `am start`, **без `pm clear`** (он стирает учётные данные и
заводит новую учётку на боевом сервере).

**Экраны с ключом снять `screencap` нельзя**: пока код приглашения на экране, стоит `FLAG_SECURE`,
и кадр выходит чёрным. Это не дефект — так и задумано (REQ-007, G3). Чтобы их всё-таки увидеть,
есть два класса, которые рисуют их в своём процессе и кладут PNG:

```bash
ANDROID_SERIAL=<устройство> ./gradlew :app:connectedDebugAndroidTest \
  -Pandroid.testInstrumentationRunnerArguments.class=com.kert0n.medapp.ui.medkit.SharingScreenShot
```

Файлы окажутся во внутренней папке приложения, и Gradle удаляет его после прогона. Чтобы забрать
их, приложение ставится руками:

```bash
adb -s <устройство> install -r -t app/build/outputs/apk/debug/app-debug.apk
adb -s <устройство> install -r -t app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s <устройство> shell am instrument -w \
  -e class com.kert0n.medapp.ui.medkit.SharingScreenShot,com.kert0n.medapp.ui.medkit.JoiningScreenShot \
  com.kert0n.medapp.test/com.kert0n.medapp.HiltTestRunner
adb -s <устройство> exec-out run-as com.kert0n.medapp cat files/shots/20-shared.png > 20-shared.png
```

Чтобы было что снимать, нужны: местная полка с парой коробок, вторая полка для переноса, идущее
лечение с нехваткой и хотя бы одна незакрытая операция в очереди (проще всего — выключить связь
`svc data disable`, что-нибудь изменить и включить обратно).

## Свои экраны U6

| экран | состояние | что должно быть видно |
|---|---|---|
| `20-sharing` | `local` | «Станет общим» и «Останется у вас» карточками со значками, предупреждение о необратимости, кнопка внизу |
| `20-sharing` | `confirm` | вопрос «Сделать «…» общей?» с тем же предупреждением |
| `20-sharing` | `on-its-way` | «Решение об аптечке уже едет серверу», приглашения нет |
| `20-sharing` | `shared` | QR, код в рамке со значком копирования, «Код скопирован», «Примерно до …», строка полного экрана, кнопка «Обновить код» |
| `21-invitation` | `full-screen` | код во весь экран на светлой подложке при любой теме |
| `22-joining` | `empty` | поле кода со значком ключа, объяснение, кнопка |
| `22-joining` | `invalid` | «Такого приглашения нет. Попросите новый код.» и поле в цвете беды |
| `23-removal` | `local` | две судьбы строками со значком и последствием, «Отмена» одной кнопкой |
| `23-removal` | `shared` | три судьбы, «Выйти и оставить остальным», перечень затронутых лечений |
| `28-sync` | `empty` | «Всё доехало» и время последнего обмена |
| `28-sync` | `rows` | три вида строк: ждёт, отвергнута с причиной и пересчётом, нечитаемая |
| `28-sync` | `offline` | «Связи нет — очередь подождёт» (выключить связь и обновить) |
| место «Опции» | `root` | список строк, «Синхронизация» со значком беды, когда очередь чего-то ждёт |
| нехватка | `remedies` | лист снизу: «Что можно сделать» и три выхода со значками |

## Задетые чужие экраны

| экран | состояние | почему задет |
|---|---|---|
| `2-med-kits` | `publishing` | пометка «Публикуется» у полки в списке |
| `2-med-kits` | `join` | значок «Присоединиться к аптечке» в верхней панели, в том числе при пустом списке |
| `4-contents` | `in-flight` | пометки «Изменение в пути» и «Коробка не у нас» на строках коробок |
| `6-package-card` | `order` | порядок секций: сколько есть → сроки → где лежит → что это |
| `14-course-card` | `shortage` | нехватка нажимается и ведёт к листу исправления |

## Тёмная тема и поворот

Пара снимков на самых плотных экранах, как в U1: `28-sync/rows` и `20-sharing/shared` в тёмной
теме, `23-removal/shared` в повороте. Каждый экран темнить и поворачивать не нужно.
