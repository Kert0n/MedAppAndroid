# U5 — что снять руками

Снимки делает владелец (решение 2026-09-16). PR оставляет **список**, а не картинки.

Куда класть: `docs/screens/<AVD>/<NN-экран>/<состояние>.png`, `screencap` как есть, без обработки.
Устройства — `Sm29` (API 29, 360×640 dp) и `BigScaled` (540 dpi, шрифт ×1.3, 398×887 dp).

Перед проходом: `am force-stop` + `am start`, **без `pm clear`** (он стирает учётные данные).
Чтобы было что снимать, нужны: идущее лечение, коробка со сроком годности «сегодня» и хотя бы один
приём прошлого дня без ответа (проще всего — не отвечать на вечерний приём и войти назавтра).

## Свои экраны U5

| экран | состояние | что должно быть видно |
|---|---|---|
| попап срока | `one` | «Сегодня истекает срок годности», карточка препарата, крестик в углу |
| попап срока | `many` | несколько карточек списком, крестик один |
| попап срока | `from-card` | на карточке коробки попапа **нет**; вернулся на место — попап снова виден |
| попап пропущенного | `rows` | «Без ответа за прошлые дни», у строк день и время, «пропущен», «Принял» |
| попап пропущенного | `then-expiry` | после крестика пропущенного — попап срока, по одному окну |
| `12-day` | `no-notifications` | строка «Напоминания не приходят» с пояснением и стрелкой |
| `12-day` | `muted-channel` | строка «Напоминания о приёмах выключены» (заглушён канал «Приёмы») |
| `12-day` | `inexact-alarms` | строка «Напоминания могут опаздывать» — вместо первой, не вместе с ней |
| `15-course-form` | `permission` | системный диалог разрешения поверх формы сразу после «Начать лечение» |
| шторка | `take` | «Принял» записал без приложения; не вышло — уведомление «Не записано: …» |
| `17-source-picking` | `expired` | просроченная коробка: «Просрочена: годна до …», подключается |
| `17-source-picking` | `expired-attached` | после подключения просроченной — одно окно «Коробка просрочена» |
| `17-source-picking` | `cards` | коробки карточками: значок, граница, аптечка и «свободно», непригодная — погашенной |
