# Запись демонстрации

`demo.mp4` — показ приложения к защите: 2:37, портрет, **без звука** (закадровый текст читается
вживую по сценарию `docs/Final/Сценарий демонстрации.md` зонтичного репозитория).

Снимает запись **обход** `app/src/androidTest/java/com/kert0n/medapp/tour/DemoFilm.kt`. Это не
проверка: тот же мир `TourWorld`, что и у снимков экранов, проходится по сюжету, но медленно —
так, чтобы зритель успевал прочесть экран. Состояния, которые вживую за две минуты не создать
(просроченная пачка, чужая бронь, изменение в пути, отказ сервера по версии, нехватка у лечения),
мир заводит заранее.

## Что в кадре

| время | сцена |
|---|---|
| 0:00 | аптечки; при входе — приёмы без ответа за прошлые дни |
| 0:06 | «Домашняя»: просроченная пачка и отбор по ней |
| 0:22 | карточка упаковки: остаток, срок, бронь |
| 0:30 | лечение: карточка курса со строкой нехватки |
| 0:38 | источники лечения; поиском подключается вторая пачка |
| 0:54 | пачка с ближним сроком переставляется наверх, обеспечение пересчитывается |
| 1:10 | план дня; карточка пункта и ответ «Принял» |
| 1:26 | шторка: напоминание с ответами, не открывая приложение |
| 1:34 | общая аптечка: чужая бронь, «Изменение в пути», отказ сервера по версии |
| 1:58 | приглашение в общую аптечку |
| 2:06 | отчёты: сводка, расход, истрачено |
| 2:22 | сканер и форма новой упаковки, заполненная ответом реестра |

**Чего в кадре нет и почему.** Обход идёт без сети (так видно всё, что ещё едет к серверу),
поэтому ключ приглашения и QR сервер не выдаёт: экран приглашения показан до выдачи ключа, а сам
ключ снят отдельным снимком — `docs/screens/21-invitation`. Камера эмулятора кода с упаковки не
видит: DataMatrix читает тот же ML Kit, что и сканер в приложении, но с настоящей фотографии
коробки (`androidTest/assets/scan/charcoal.jpg`), а дальше идёт обычный путь приложения — форма
уже знает то, что сказал реестр.

**Почему это не слайд-шоу.** Внутри проверки часы Compose стоят и прыгают вперёд только там, где
проверка ждёт покоя: переход при этом проскакивает целиком. Поэтому обход крутит кадры сам, в
настоящем времени (`play`), а нажимает **системным событием** (`input tap`) — иначе ни волны
нажатия, ни перехода на записи не будет, экран просто вдруг станет другим. Системный кружок
«показывать касания» в запись не попадает: его рисует не приложение, — и вместо него видно то,
что рисует сам экран: волну под пальцем, выезд экрана, всплытие и гашение диалога.

## Как переснять

```bash
./gradlew :app:assembleDebug :app:assembleDebugAndroidTest
adb -s emulator-5554 install -r -t app/build/outputs/apk/debug/app-debug.apk
adb -s emulator-5554 install -r -t app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s emulator-5554 shell screenrecord --size 720x1600 --bit-rate 8M --time-limit 180 /sdcard/demo.mp4 &
adb -s emulator-5554 shell am instrument -w -e tour true \
  -e class com.kert0n.medapp.tour.DemoFilm com.kert0n.medapp.test/com.kert0n.medapp.HiltTestRunner
adb -s emulator-5554 shell pkill -INT screenrecord
adb -s emulator-5554 pull /sdcard/demo.mp4 raw.mp4
# начало — до запуска приложения, конец — остановка записи: оба обрезаются
ffmpeg -ss 2.2 -to 154.2 -i raw.mp4 -vf scale=540:-2 -c:v libx264 -crf 28 -preset slow \
  -pix_fmt yuv420p -an -movflags +faststart docs/demo/demo.mp4
```

Приложение ставится **руками**: `connectedDebugAndroidTest` удаляет его после прогона. Темп показа
задаёт `PACE` в `DemoFilm`; границы обрезки сверяются с длиной нового прогона, а не берутся отсюда.
