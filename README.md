# MedApp — Android-клиент

Мобильный клиент [MedApp](https://github.com/Kert0n/MedAppDocs): учёт домашней аптечки, общие аптечки,
синхронизация офлайн-изменений с [сервером](https://github.com/Kert0n/MedAppServer).

Приложение собрано и работает: аптечки и упаковки, курсы лечения с планом дня и напоминаниями,
общие аптечки с бронями участников, отчёты, сканер кода маркировки и очередь, которая довозит
изменения до сервера, когда связь появится. Без сети работает всё, кроме того, о чём знает только
сервер. `minSdk 29`, `targetSdk 37`, проверка на каждый пуш, публикация сборки из `main`.

Набор экранов доводится PR-ами U-серии; что уже есть — видно по снимкам и записи показа.

## Обращения и изменения

Для дефекта, продуманного изменения или находки безопасности используйте соответствующий шаблон
[GitHub Issues](https://github.com/Kert0n/MedAppAndroid/issues/new/choose). PR заполняется по
репозиторному шаблону, ссылается на раздел PLAN/REQ и получает метки областей по изменённым путям.
Клиентские риски и возможные ошибки на границе серверного протокола остаются issue Android-клиента.
Изменение самого API предлагается отдельно в
[MedAppServer](https://github.com/Kert0n/MedAppServer/issues/new/choose).

Коротко о продукте: приложение считает **физические упаковки** лекарств — где лежат, сколько
осталось, когда истекают, кому обещаны. Курс лечения расходует не «препарат вообще», а стек
конкретных пачек в заданном порядке. Аптечкой можно поделиться, и тогда пачки живут на сервере —
но срок годности, доза, заметка и цена остаются только на устройстве: [сервер](https://github.com/Kert0n/MedAppServer)
приватен по замыслу и не хранит ни дат, ни истории приёмов.

## Установка

Последняя сборка `main` лежит в релизе [latest](https://github.com/Kert0n/MedAppAndroid/releases/tag/latest)
— файл зовётся своей версией, например `medapp-1.7-release.apk`. Кладёт его туда CI после того,
как «Проверка» на `main` прошла: минорная версия растёт с каждой публикацией, прежняя сборка из
релиза уходит.

## Сборка

```bash
./gradlew assembleDebug
```

Понадобится Android SDK; путь к нему — в `local.properties`, в git этот файл не попадает. Там же
живут параметры сборки: адрес сервера, регистрационный токен и подпись release. Без них debug
соберётся со значениями по умолчанию, а release не соберётся вовсе — `verifyReleaseSecrets`
назовёт, чего не хватает. Ключ подписи в репозиторий не попадает никогда (`/keystore/`).

## Контракт сервера

Полный контракт — [open-api.yaml](https://github.com/Kert0n/MedAppServer/blob/main/open-api.yaml)
в репозитории сервера; его можно открыть, не поднимая приложение.
